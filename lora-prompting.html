14Low-Rank Adaptation (LoRA)低秩適應 LoRA

全量微調要更新數十億參數，又貴又易過擬合。LoRA 假設微調的改變量 ΔW 是「低秩」的，所以寫成 ΔW = B(n×r)·A(r×k)，r 很小。原本的 W₀ 凍結不動，只訓練 A 和 B；A 隨機初始化、B 設為 0，開始時 ΔW = 0。部署時把 W₀ + BA 合併，推理不會變慢。

例子一層 512×64 = 32,768 個參數；r = 8 時只需訓練 512×8 + 8×64 = 4,608 個，少 86%。比喻：一本厚字典（W₀）不改動，只在旁邊貼幾張便利貼（BA）記下新用法；換另一科目就換另一疊便利貼。

15Prompting and in-context learning提示與情境學習

提示 = 給模型的指示、問題和例子。CO-STAR 框架：情境、目標、風格、語氣、受眾、回應格式。情境學習 (ICL) 是在提示中放幾個例子，模型不改參數就學會任務。思維鏈 (CoT) 叫模型寫出中間步驟；自洽性 (self-consistency) 生成多條推理再投票。

例子ICL：「好好味！→ 正面；好難食 → 負面；服務一流 → ？」模型答「正面」。零樣本 CoT：在題目後加「Let's think step by step」，數學題準確度大增。

16Families of models and distillation模型家族與蒸餾

由一個大模型製作一系列較小模型：先「剪枝」（用少量數據前向傳播，評估哪些層、注意力頭、神經元不重要，然後剪走），再「蒸餾」（小模型學習大模型的輸出）。寬度剪枝（縮小 E、H）比深度剪枝（刪層）效果好。

例子NVIDIA 把 Llama-3.1 8B 剪枝蒸餾成 4B 的 Minitron，只用 940 億個 token 訓練（原模型用 15 萬億）。

17LLM benchmarks大型語言模型評測基準

用標準試題比較模型：HellaSwag（常識：選最合理的下文）、WinoGrande（代名詞指誰）、MMLU（57 科選擇題）、ARC（抽象推理）、GSM8K（小學數學應用題）、MBPP（Python 編程）。「shots」= 提示中給幾多個例子。

例子WinoGrande 例題：「獎盃放不進手提箱，因為它太大。」問「它」是獎盃還是手提箱？（答：獎盃）。人類準確率 94%。

18DeepSeekDeepSeek

DeepSeek-V3：6,710 億參數的混合專家模型 (MoE)：每個 token 只啟動少數「專家」前饋網絡，所以運算便宜；14.8 萬億 token 預訓練，訓練費用少於 560 萬美元。R1-Zero 只用強化學習 (GRPO) 訓練推理，獎勵來自規則（答案對不對、格式對不對），模型自己學會「aha moment」和更長的思考。R1 加入 SFT 解決可讀性和中英夾雜問題。

02From pre-training to a useful model由預訓練到可用模型

Generative AI project lifecycle: (1) identify the functions you need; (2) train from scratch or reuse an existing model (base, reasoning, instruction, multimodal); (3) adapt it with prompt engineering, fine-tuning and/or alignment; (4) assess performance; (5) optimise for deployment and user experience; (6) acknowledge and work around LLM limitations.

03Fine-tuning and its problems微調及其問題

How much data do you have?

  • Lots → train from scratch
  • Medium → fine-tune
  • Sparse → use the general model (prompting)

Fine-tuning (= transfer learning) updates a pre-trained model's parameters with new data, adapting to the target task while keeping its general knowledge.

Approaches

  • All parameters
  • Last k layers only (e.g. k = 2)
  • Bias terms only
  • Adapter tuning: insert 2 small FC layers; adds inference latency
  • Catastrophic forgetting 災難性遺忘: better on the new task, worse on others. Mitigation: fine-tune across a wide range of instruction types.
  • Retraining billions of parameters needs huge compute, memory, time, energy and money.
  • With little new data, full fine-tuning overfits.

04LoRA: Low-Rank Adaptation低秩適應

Hu et al., Microsoft, 2021 (~44k citations). The main way to fine-tune large models cheaply.

Background: rank 秩

  • Rank = number of linearly independent columns (or rows). For W (n×k), rank(W) ≤ min(n, k).
  • e.g. [[1,2],[2,4]] has rank 1: the second row is twice the first.
  • Low-rank: rank ≪ min(n, k). Any rank-r matrix factors as W = B(n×r)·A(r×k).
  • Hypothesis: the change ΔW from fine-tuning is low-rank.
W₀ + ΔW = W₀ + B(n×r)·A(r×k) r ≪ min(n, k) (typical r = 4 to 32) Forward pass: h = W₀x + BAx Trainable: nr + rk instead of nk Example: n×k = 512×64 = 32,768 ; r = 8 → 512·8 + 8·64 = 4,096 + 512 = 4,608 (86% fewer) Deploy: compute and store W = W₀ + BA once → no extra inference time GPT-3 175B: 175 billion → ~17 million trainable (≈ 10,000× fewer)

Advantages

  • Orders of magnitude fewer trainable parameters → less training time, GPU memory and cost.
  • Less overfitting: original weights fixed, generalisation preserved.
  • No extra inference latency (unlike adapters): merge BA into W₀.
  • Easy task switching: one copy of W₀ + small (A, B) per task.
  • r is small and can be tuned for best results.

How r is chosen (May 2025 Q4)

  • Larger r: more capacity, more training memory.
  • Depends on training-GPU memory, amount of fine-tuning data, and the quality you need.
  • Not on the inference GPU (BA is merged).

05GPU memory for fine-tuning微調所需記憶體

Example from the slides: fine-tune Llama-2-7B on one GPU. Training needs the weights, a gradient for each trained weight, and Adam's two optimiser states (m and v) per trained weight.

Weights7B × 4 = 28 GBINT8: 7B × 1 = 7 GB
Gradients7B × 4 = 28 GBFP16: 1 × 2 = 2 GB

The slide's 2 GB and 4 GB count gradients and optimiser states for about 1 billion values; with LoRA only the small A and B matrices need them.

  • Quantisation to 8-bit integers causes rounding errors (values snapped to the nearest level) and clipping errors (values outside the range cut off). A good scheme keeps the quantised distribution close to the original.
  • GPUs on the slide: H100 80 GB, A100 80/40, V100 32/16, RTX4090 48*, A10G 24, T4 16, RTX4080 16. (*The slide says 48; the standard RTX 4090 has 24 GB.)

06Prompting and prompt engineering提示與提示工程

  • A prompt is the user's input (instructions, questions, examples) telling a model what task to do, e.g. "Cat as a scientist conducting experiments in a lab" for Stable Diffusion.
  • Prompt engineering = carefully designing prompts to get a specific output. It's empirical: effects vary a lot between models, so a prompt for one model may not work on another.
CO-STARMeaningSlide example (Facebook post for Alpha's hairdryer "Beta")
ContextBackground information"I want to advertise my company's new product. Company Alpha, product Beta, an ultra-fast hairdryer."
ObjectiveThe task"Create a Facebook post that gets people to click the product link to buy it."
StyleWriting style"Follow successful companies that advertise similar products, such as Dyson."
ToneAttitude"Persuasive."
AudienceWho it's for"Mostly the older generation; target what they look for in hair products."
ResponseOutput format"The Facebook post, concise yet impactful."

CROFTC vs CO-STAR

  • Context = Context
  • Role: assign an identity, "You are a marketing copywriter…" (≈ Style)
  • Objective = Objective
  • Form: output structure, "a numbered list" (= Response)
  • Tone = Tone
  • Conditions: boundaries, "under 10 words", "avoid technical terms"
  • Only CO-STAR has Audience.

More tips from the slides

  • Treat it like a person: interactive, multi-step questions.
  • Set the stage with a role or context ("act as a lawyer", "I'm a beginner runner…").
  • Ask it to write prompts for you.
  • Curb hallucination: "Why do you think that?", "What evidence supports your answer?"
  • Negative prompting: "Don't write anything offensive, harmful or factually incorrect."
  • Experiment and rephrase; answers change between tries.

Does tone matter? Asked for 1,000 baby names, the plain prompt produced 50–100 names after hedging. Polite or flattering prompts did no better; threatening prompts did significantly worse.

07In-context learning情境學習

In-context learning (ICL) = few-shot prompting: put task demonstrations in the prompt and let the frozen model infer the pattern (e.g. "Review: Delicious food! Sentiment: Positive … Review: Good meal! Sentiment: ___").

In-context learningFine-tuning
ParametersUnchanged (frozen)Updated by training
FlexibilityOn the fly, any task, no retrainingRetrain per task
ResourcesJust inferenceExtra compute and labelled data

Why does it work? Still researched; it seems to be an emergent ability from pre-training. Two explanations on the slides: (1) the model computes "meta-gradients" from the demonstrations in its forward pass and implicitly does gradient descent through attention; (2) implicit Bayesian inference: the prompt helps the model "locate" a concept it learned in pre-training.

09Prompt tuning (P-tuning)提示微調

Not prompt engineering. A small trainable model produces task-specific virtual tokens (soft prompts) that are prepended to the prompt before the frozen LLM. Motivated by token budget. Advantages: parameter-efficient (a small set of soft prompts vs full fine-tuning), swap prompts per task, and at inference the P-tuning model can be replaced by a lookup table.

10Context engineering and RAG情境工程與檢索增強生成

  • The model is stateless: it remembers nothing between calls ("Do you know my name?" "You never told me."). Apps store the chat history and re-send it each turn.
  • When input exceeds the context (block) size, it must be truncated; old or unimportant messages are dropped first, so the model "forgets" the start. Context engineering = systematically deciding what to keep and drop.
  • LLM weaknesses: don't know what they don't know (hallucination), out-of-date knowledge, may draw on unreliable sources.
Why GPT hallucinates, and fixes (Dec 2025 Q6)
  • Cause: the base model produces the most plausible continuation, not the most truthful; training data has errors and misses recent events; it has no built-in sense of true vs false and guesses when data is sparse. (Plus the long-tail sampling effect from lecture 7.)
  • Fixes on the slides: RAG (supply facts from external sources as context); fine-tune for factuality (e.g. learn to say "I don't know"); prompting ("explain your reasoning", "don't guess if unsure"); self-checking (ask the model to review and correct its output).

11GPT-4, data and GPT-5GPT-4、訓練數據、GPT-5

GPT-4 (2023)

  • Multimodal (image + text). No architecture, size, data or training details released (guesses: ~1.7–1.8T params).
  • Simulated bar exam: top ~10% (GPT-3.5: bottom 10%).
  • >25,000-word responses vs ~3,000 for GPT-3.5.
  • 82% less likely to answer disallowed requests; 40% more likely to be factual.
  • Context 8,192 (32,768 version) vs 4,096 / 2,048 before.

GPT-5 (2025)

  • Unified model selector: decides how much processing a request needs.
  • ~80% fewer factual errors; willing to say "I can't do that".
  • Builds apps in seconds; strong on tests and maths competitions.
  • Better medical answers (clarifying questions), multimodal (charts, diagrams, photos). Sizes: GPT-5, mini, nano.
  • Garbage in, garbage out. Trillion-parameter models need trillions of tokens (GPT-4: ~13T tokens). Raw web text is noisy: formatting, spam, duplicates, misinformation. Common Crawl (~250B pages, open) is the biggest free source (FineWeb cleans it). GPT-3 filtered 45 TB to 570 GB.
  • GPT-3 data mix: Common Crawl 400 GB (60% weight, 0.44 epochs), books 67 GB (16%, 2.33), WebText 20 GB (21%, 2.9), Wikipedia 3 GB (3%, 3.4). High-quality sources are seen several times.
  • Compute-optimal (Chinchilla): large models are more sample-efficient, but model size and training data should scale equally (2× params → 2× data). A big model without enough data is wasted; many models should be smaller and trained longer.

12Model families: pruning and distillation剪枝與蒸餾

NVIDIA built smaller models from a large one: 15B → 8B → 4B (Llama-3.1-Minitron 4B from Llama-3.1 8B).

  1. Pruning: start from the trained LLM → estimate importance of layers, heads, neurons and embedding channels using only forward passes on a small calibration set (1,024 samples), simpler than gradients → rank → trim.
  2. Distillation: the pruned student learns from the teacher's outputs (logits), plus intermediate losses (embedding output, MLP input, block output, LM head), recovering accuracy with far less data.

Findings: width pruning (shrink E and H) beats depth pruning (drop layers); the 4B model is below the 8B overall but smaller models can win on specific tasks; it needed only 94B training tokens vs 15T for Llama-3.1 8B.

15Exam-style practice考試式練習

1. A layer has W of size 4096 × 4096. With LoRA rank r = 8, how many trainable parameters, and what is the reduction factor?

Show answer
full: 4096 × 4096 = 16,777,216 LoRA: 4096·8 + 8·4096 = 65,536 reduction: 16,777,216 / 65,536 = 256× (99.6% fewer)

2. Fine-tuning a 13B model fully in FP32 with Adam: how much memory for weights, gradients and optimiser states? Can it fit on one 80 GB GPU?

Show answer
weights 13 × 4 = 52 GB ; gradients 52 GB ; Adam m, v: 2 × 52 = 104 GB total = 208 GB → no; needs ≥ 3 × 80 GB GPUs, or LoRA + quantisation

3. Why is LoRA initialised with A random and B = 0? What would go wrong if both were 0?

Show answer

B = 0 makes ΔW = BA = 0, so fine-tuning starts exactly at the pre-trained model. A random gives B a non-zero gradient (∂L/∂B depends on Ax); if A were also 0, both gradients would be 0 and nothing would ever train.
